【必读：什么是 ROUTING_KEYWORDS？】

本项目使用「双模型路由」机制：
  - 纯聊天请求 → 轻量快速的 chat 模型（无工具）
  - 需要工具的请求 → 有推理能力的 reasoner 模型（有工具）

路由判断依赖关键词匹配。如果你的 MCP 没有声明 ROUTING_KEYWORDS，
用户的相关请求可能被路由到 chat 模型，导致工具完全无法被调用。


------------------------------------------------------------
【必须添加】ROUTING_KEYWORDS
------------------------------------------------------------

每个 MCP 文件的 mcp = FastMCP(...) 下方，必须添加：

    ROUTING_KEYWORDS = ["关键词1", "关键词2", "关键词3"]

填写规范：
  ✅ 写用户可能说出的自然语言词语（中文为主）
  ✅ 包含同义词、简称、常见叫法（如 "MC" / "我的世界" / "minecraft"）
  ✅ 5~15 个词为宜，不要过多（避免误触发）
  ❌ 不要写过于通用的词（如 "帮我"、"查询"、"你好"）——会导致几乎所有对话都走 reasoner，变慢
  ❌ 不要写正则特殊字符（如 . * ? + [ ]），系统会自动 escape，但写了没意义


------------------------------------------------------------
【示例】
------------------------------------------------------------

# 正确示例：天气 MCP
from mcp.server.fastmcp import FastMCP
mcp = FastMCP("WeatherMCP")

ROUTING_KEYWORDS = ["天气", "气温", "下雨", "晴天", "预报", "穿什么衣服"]

@mcp.tool()

------------------------------------------------------------
【工作原理（简述）】
------------------------------------------------------------

1. 程序启动时，自动扫描所有已加载 MCP 的 ROUTING_KEYWORDS
2. 将所有关键词合并进路由正则表达式
3. 用户每次发消息时，正则匹配决定走哪个模型
4. MCP 被禁用或删除后，重启程序关键词自动消失，无需手动清理


------------------------------------------------------------
【如果你的 MCP 不写 ROUTING_KEYWORDS 会怎样？】
------------------------------------------------------------

  - 路由器不认识你的工具触发词
  - 相关请求走 chat 模型，chat 模型没有工具列表
  - 模型会用文字假装执行，或直接说"做不到"
  - 功能实际上完全无法工作

如果你的插件是纯辅助性质（不需要用户主动触发，只被其他工具调用），
可以不写 ROUTING_KEYWORDS，但请在文件顶部注释说明原因。
